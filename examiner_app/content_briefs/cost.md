# Cost and runtime: verified facts brief

Page id `cost`. Question: how much time and compute do scalar and channel-wise decay need to train and to run?
Built from saved artifacts. The export is generated by `server/build_cost_export.py` into `server/data/cost_export.json`.
Parameter counts are computed live from `recipe_model.RecipeLM` on CPU (`server/cost_data.py`).

## Hardware labels (never mixed in one comparison)
- **A6000**: NVIDIA RTXA6000-12Q (A6000 profile). Measured. Source: `output/a6000_recipe_timing_20261116_083756_121/`.
  Each run: 50 optimizer steps, FP32, effective batch 512 examples, microbatch 32, chunked backend, 100,000 training examples.
  "parallel" = two workers sharing GPU 0 at the same time. "sequential" = one worker after the other.
- **Kaggle GPU (Tesla T4)**: measured. Source: `research_results/published_recipe_timing_20261116/`.
  Same recipe settings (50 steps). The saved summary does not record whether the two workers shared a GPU, so the mode is "not recorded".
- **CPU**: not used for timing. `output/a6000_recipe_timing_20261116_083251_635/` and `..._083154_572/` are CPU smoke runs of a
  tiny configuration (11,816 and 12,896 parameters). Excluded.

## Parameters (verified live from the constructors)
- Scalar: 1,585,416 parameters. Channel-wise: 1,651,456 parameters.
- Difference: +66,040 parameters = +4.17% of the scalar model (4.1655%).
- Per layer: +16,510 = a_proj 128x128 minus 128x1 (+16,256), plus A_log (+127) and dt_bias (+127). Four layers: 66,040.
- Settings: width 128, vocabulary 8,192, length 64, 4 layers, one head, decay gate width 1 (scalar) or 128 (channel-wise).
- The match with the saved summaries holds: `output/a6000.../mqar/parallel/scalar/summary.json` reports 1,585,416 and channel-wise 1,651,456.
- Other model sizes (not the recipe): `output/full_research` 10M-scale models: 3,329,760 vs 3,479,520 (+149,760, +4.50%);
  `output/tinystories/10M`: 10,030,880 vs 10,155,680 (+124,800, +1.24%). These are different models, so they are not comparable to the recipe.

## Recurrent state (verified from constructors, not a saved number)
- Per layer, one head: state shape 256 x 128 (value width x key width), 32,768 floats, 131,072 bytes in FP32. Four layers: 524,288 bytes.
- Identical for scalar and channel-wise: the decay gate changes its vector length, not the state's shape.
- The per-token state update in `serial_rectangular` (`state = state * alpha[:, index].unsqueeze(-2)`) broadcasts to the same state-sized tensor in both models.

## Per-token gate cost (verified from constructors)
- Gate projection multiply-adds per token: scalar 128 per layer (512 total); channel-wise 16,384 per layer (65,536 total).
- Extra: 65,024 multiply-adds per token across four layers. Compared with all Linear layers in the model, computed live (see endpoint).

## Measured training step time (recipe model, optimizer steps only, 50 steps per run)
A6000, mean step seconds (standard error in brackets):

| family | mode | scalar | channel-wise | channel vs scalar |
|---|---|---|---|---|
| MQAR | parallel | 1.0317 (0.0084) | 1.0647 (0.0118) | +3.2% |
| MQAR | sequential | 0.7620 (0.0077) | 0.7689 (0.0067) | +0.9% |
| overwrite | parallel | 1.0574 (0.0084) | 1.0561 (0.0109) | -0.1% |
| overwrite | sequential | 0.7986 (0.0159) | 0.7926 (0.0079) | -0.7% |

Kaggle T4 (mode not recorded), mean step seconds:

| family | scalar | channel-wise | channel vs scalar |
|---|---|---|---|
| MQAR | 1.0282 (0.0161) | 1.0874 (0.0160) | +5.8% |
| overwrite | 1.1027 (0.0153) | 1.1443 (0.0153) | +3.8% |

Reading: on the A6000 the channel-wise gap changes sign between families and modes. Gap divided by the standard error of the
difference: MQAR parallel about 2.3, MQAR sequential about 0.7, overwrite parallel about 0.1, overwrite sequential about 0.3.
On the T4 channel-wise was slower in both families (about 2.6 and 1.9). These are one 50-step window per run, not repeated seeds.

Examples per second = 512 / mean step seconds (A6000 sequential about 640 to 670; parallel per worker about 480 to 500).

## Projected training time (A6000 benchmark report, 64 epochs = 12,544 optimizer steps)
- Pair (scalar and channel-wise together, same family):
  - MQAR: parallel 13,392 s (about 3.7 h) estimated; sequential 19,277 s (about 5.4 h). Parallel recommended.
  - Overwrite: parallel 13,337 s (about 3.7 h); sequential 20,100 s (about 5.6 h). Parallel recommended.
- Conservative (adds timing margin and reserve): MQAR parallel 16,983 s; overwrite parallel 16,934 s.
- Per model, parallel estimates: MQAR scalar 12,981 s, channel-wise 13,392 s; overwrite scalar 13,337 s, channel-wise 13,329 s.
- Per model, sequential: MQAR scalar 9,596 s, channel-wise 9,681 s; overwrite scalar 10,086 s, channel-wise 10,014 s.
- Sanity check: 12,544 x measured mean step time is within about 0.3% of the saved estimate. The saved estimate also includes setup, validation and checkpoints.
- Joint-calibration sessions (A6000, 16 epochs = 3,136 steps per model), measured pair times: MQAR 3,364 s, overwrite 3,402 s.
  This is for a proposed joint initialization that has not been trained. Shown only as a second A6000 measurement.

## Energy and memory
- Recipe runs (A6000 or Kaggle T4): no energy reading and no memory reading in the saved summaries. `benchmark_single_gpu_recipe.py` does not call the energy or memory helpers.
  Stated on the page, not estimated.
- A6000 NVML: `output/full_research` runs report "NVML exposes neither a total-energy counter nor GPU power samples". Energy not supported on this A6000 profile.
- Other models, memory only: A6000 training peak allocated memory 2,384,745,472 bytes (scalar, 3.3M model) and 2,409,144,832 bytes (channel-wise, 3.5M model), identical across seeds 42 to 46.
- Other models, energy (Kaggle Tesla T4, 10M TinyStories, seed 42 only, 1,000 steps, 16,384,000 tokens):
  channel-wise 496,810 J over 15,224 s; scalar 569,987 J over 16,050 s. Single seed, different model: directional only.
  The 30M and 55M folders had NVML initialisation failures (30M) or are repeated 30M records (55M). Not used.

## Decode (run) cost, other model only
- `output/full_research` 10M-scale models, A6000, 256-token context, 5 seeds per variant. Mean ms per generated token:
  scalar about 5.5, channel-wise about 5.4 (seed 42: 5.54 and 5.39). The difference is within the seed spread. Other model only.
- No decode timing exists for the recipe model.

## Conflicts and notes
- `A6000_TIMING.md` describes the benchmark and says estimates are short-run projections. Consistent with the report.
- `decay_design_results.md` gives published TinyStories sizes (10M, 55M, 100M) and losses. It contains no runtime. Not used for cost.
- The three `output/a6000_recipe_timing_*` folders are one A6000 run and two CPU smoke runs. The brief uses only the A6000 folder.
- `output/tinystories/55M` duplicates the 30M metrics (byte-identical). Excluded.
- The full-research gate overhead (149,760) and the recipe gate delta (66,040) are different models. Page shows both with labels.
