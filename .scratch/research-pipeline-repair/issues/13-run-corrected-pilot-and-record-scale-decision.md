# 13: Run a corrected pilot and make a costed go/no-go decision

**What to build:** The researcher receives one scientifically valid corrected pilot, a clear interpretation of its results and a realistic replication budget before deciding whether to spend more compute.

**Blocked by:** 10: Qualify learnability and lock a feasible training recipe; 11: Produce analysis that handles missing runs and uncertainty correctly; 12: Separate worker capacity testing from isolated efficiency measurement.

**Status:** pilot plan committed; fresh corrected run and go/no-go pending explicit compute authorization

- [ ] Before execution, estimate training, calibration, validation, evaluation, isolated benchmarking and failure allowance using the corrected measured workload; record total compute and wall time.
- [ ] Researcher authorization to spend that compute is recorded separately from implementing the pilot workflow or passing a smoke test.
- [ ] Once authorized, one fresh paired seed completes scalar/channel-wise by default/calibrated conditions across both corrected synthetic families, under the frozen protocol and fresh identities.
- [ ] Full held-out results include shortcut-baseline comparisons, symbolic-oracle bounds, learning curves, joint difficulty/error strata and paired gate-sharing interventions.
- [ ] Apparent mechanism claims are checked against intervention behavior and recipe sensitivity; underlearning or unexplained reversals trigger investigation rather than a superiority claim.
- [ ] The recorded go/no-go decision states whether validity, learnability, scientific interest and resource requirements support replication, or which stage must be revisited.
- [ ] Further seeds, grouped-4, language modeling and a second scale receive a prospective scoped decision; the previous full run matrix cannot launch automatically.
- [ ] Proposal, run guidance, claims table and limitations match the executable corrected protocol and actual parameter counts, while preserving legacy results as exploratory evidence.
